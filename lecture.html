An image is a tensor of measurements.

A color image has height, width and color channels. A training batch adds another dimension. Our small CNN reads grayscale images with shape [batch, 16, 16, 1].

Nearby pixels contain useful structure. A convolution checks local patterns while sharing the same weights across positions.

Technical walkthrough: dimensions, preprocessing and memory

A 640 × 480 RGB frame contains 921,600 color values. Uint8 storage takes about 0.92 MB, while float32 takes about 3.69 MB, before extra tensors. A 30-frame/second stream would contain about 27.6 MB/second of uncompressed uint8 RGB values. Those are raw-array estimates, not encoded video file sizes or measured browser throughput.

Our symbol generator directly produces float32 values in [0,1]. The ball detector wrapper accepts a canvas and performs its own model preprocessing. Apply the normalization expected by the specific model. Dividing every model input by 255 without checking its contract can break inference.

Changing width and height independently can squash a round ball. Ball Remix preserves the frame aspect ratio, places it inside a square, then maps detected boxes back by subtracting the padding.

Engineering check: record shape, dtype, color order, resize rule and model version. A correct neural network with the wrong input contract still gives bad predictions.

Learning changes the weights.

Forward → loss → backward → update → forward again. The forward pass calculates scores. A label lets us calculate a loss. Backpropagation follows the calculation backward, multiplying local derivatives and adding shared paths. The optimizer uses those gradients to change the parameters. A fresh forward pass then measures the effect of that update.

The network itself is feed-forward. Repeating this training cycle creates the learning loop. Training data, the loss and the optimizer together determine what the model can learn.

Using the model calculates an answer.

New input → forward pass → output → application action. During ordinary inference, the learned parameters stay fixed. The model does not run a backward pass simply because a new camera frame arrives. The application may still remember earlier coordinates, smooth movement, maintain a game timer, or associate detections between frames.

That memory belongs to the interaction or tracking logic. It does not automatically train the CNN or prove that the next answer will be correct.

02 / REUSE THE SAME LOCAL CALCULATION

Filters turn pixels into features

  • Multiply the pixels in a patch by the matching filter weights, then add.
  • Slide the same weights across the image: the responses form a feature map.
  • ReLU keeps positive responses; pooling summarizes nearby activations.

03 / CONVOLUTION

A small filter produces one response per patch.

Multiply matching image values and weights, then add the products. Slide the same filter to the next patch.

Vertical-edge filter

-1  0  1
-1  0  1
-1  0  1

A dark-to-bright patch

0  0  1
0  0  1
0  0  1
Each row contributes 1. The response is 3. Reverse the boundary: the response becomes −3.

A uniform patch gives zero because positive and negative terms cancel. This filter detects a local pattern, rather than recognizing an entire object.

Technical walkthrough: channels, bias, stride and padding
Z[u,v,o] = b[o] + Σ K[a,d,c,o] × X[uS+a−P,vS+d−P,c]
Output size=⌊N+2P−FS⌋+1
Learned parameters = (F × F × input channels + 1) × output channels

The sum covers kernel rows, columns and input channels. Each output channel has its own filter and bias. Weight sharing means the same filter checks every location. In the common CNN convention, the displayed kernel is not flipped: the operation is technically cross-correlation.

The calculator assumes a square input/kernel, equal stride and symmetric padding, dilation 1 and a bias per output channel. Our fixed-filter playground deliberately omits bias and learning: its displayed kernel has only nine weights.

ReLU replaces negative values with zero. Max pooling keeps the largest value in each block. These operations prepare features for a later decision.

Technical walkthrough: activation, pooling and receptive field

ReLU is max(0,z). Multiple linear operations without a nonlinear activation can collapse into a single linear map. ReLU lets a network represent more complex relationships. It also removes the negative edge response, so different learned filters may respond to opposite orientations.

Pooling shrinks spatial maps and can reduce sensitivity to small shifts. It does not guarantee that a model ignores all position changes. Strided convolutions offer another way to shrink maps. Flattening changes shape into one vector without learning weights.

A receptive field is the input region that can affect an output. For a sequence of layers, maintain jump j and receptive field r: start at 1 and 1, then use r_new = r + (F−1)j and j_new = jS. Padding changes edge behavior and coordinate alignment.

Ablation question: what changes if pooling is removed? Compare parameter count, runtime and held-out errors rather than assuming a larger model is better.

    MATH 02 / EVERY MULTIPLICATION
    Convolution reuses one set of weights across many patches.
    

    Zn,u,v,o=bo+∑a=0Fh−1∑d=0Fw−1∑c=0Cin−1Ka,d,c,oXn,uS+a−P,vS+d−P,c

    MATH 04 / THE BACKWARD RULE OF EACH GATE
    ReLU gates gradients. Max pooling routes them.
    

    A=max(0,Z)∂L∂Z=∂L∂A⊙1[Z>0]
    

    ⊙ means elementwise multiplication. The bracket is an indicator: one where the condition is true, zero elsewhere. At Z = 0 ReLU is not differentiable; the worked engine chooses derivative zero.
    

    Forward input ZReLU output AIncoming ∂L∂AOutgoing ∂L∂Z

    The unique winning cell receives the incoming derivative. Other cells get zero for this window. Overlapping pooling windows can send multiple contributions to the same input, which must add.     Why nonlinearities matter: two affine layers without an activation collapse: W₂(W₁x+b₁)+b₂ = (W₂W₁)x + (W₂b₁+b₂). ReLU prevents that collapse and changes which paths carry gradients.

    Cross-entropy and softmax simplify to p − y.
    

    sk=ck+∑jhjWkj

    Subtracting the same constant changes neither the mathematical probabilities nor their ordering. It prevents overflow when logits are large. Logits [2,1,0] and [1002,1001,1000] both give approximately [0.665241, 0.244728, 0.090031].

    ∂pk∂sj=pk(δkj−pj)

    ∂L∂sj=pj−yj

    MATH 06 / CHAIN RULE THROUGH THE WHOLE CNN
    A shared weight receives a sum of all the paths that use it.
    

    Let gk = ∂L∂sk = pk−yk. For the dense layer sk = ck + ΣjhjWkj, differentiating gives:
    

    ∂L∂Wkj=hjgk∂L∂hj=∑kWkjgk
    

    The bias gradient is gk. Reshape the feature gradient backward through flattening, route it through pooling, then multiply by the ReLU mask. Call the resulting convolution pre-activation gradient Δ = ∂L∂Z. With zero-based indices and D = 1, sum below over n=0,…,B−1, u=0,…,Hout−1 and v=0,…,Wout−1. For dilation D, the input offsets become Da and Dd.
    

    ∂L∂Ka,d,c,o=∑n,u,vΔn,u,v,oXn,uS+a−P,vS+d−P,c
    

    One kernel entry is reused at many locations, so each use contributes to the same parameter gradient. The convolution bias gradient is the sum of Δ over batch and spatial positions for that output channel. For the input gradient, scatter each Δ×K contribution back to the input coordinate it read and add overlapping contributions.
    

    A four-use numerical example: suppose a shared weight reads input pixels [1,2,0,3] at four output positions, whose Δ values are [0.2,−0.1,0.4,0.3]. Its gradient is 1×0.2 + 2×(−0.1) + 0×0.4 + 3×0.3 = 0.9. Updating once with 0.9 is different from updating the shared weight after every use during a forward pass.
    

    For mean batch loss, include a factor 1B once. If Δ already comes from a mean-reduced loss, it already contains that scaling. Dividing again would shrink every update incorrectly.

    MATH 08 / AN UPDATE IS AN ALGORITHM
    SGD follows the gradient. Adam also tracks its history.
    

    θt+1=θt−ηgt
    

    At weight 0.5, gradient +0.2 and learning rate 0.1, SGD gives 0.48. A negative gradient would increase that weight. A large step can cross a nonlinear boundary or increase the loss. Backpropagation computes a direction; it does not choose the step size.
    

    mt=β1mt−1+(1−β1)gtvt=β2vt−1+(1−β2)gt2
    

    m^t=mt1−β1tv^t=vt1−β2t
    

    θt=θt−1−ηm^tv^t+ε
    

    These operations act elementwise. With zero initial moments, g₁ = 0.2, β₁ = 0.9 and β₂ = 0.999, the first moments are m₁ = 0.02 and v₁ = 0.00004. Bias correction gives m̂₁ = 0.2 and v̂₁ = 0.04, so a conceptual Adam step with η = 0.01 is about 0.01.
    

    The running symbol CNN calls tf.train.adam(0.01). The bundled runtime reports β₁ = 0.9, β₂ = 0.999 and ε = 10⁻⁷. The displayed form matches the bundled optimizer: it bias-corrects both moments, then divides by the square root of the corrected second moment plus epsilon. The worked SGD engine intentionally exposes a simpler update rather than claiming to reproduce the full optimizer.
    

    Lbatch=1B∑n=1BLn

    DERIVATION 1 / FOLLOW ONE EDGE, THEN ADD THE PATHS
    

    A backward message is an incoming gradient multiplied by a local derivative.
    

    Suppose a scalar intermediate value v depends on x and the final loss depends on v. The forward pass saves the values needed to evaluate the local derivative. The backward pass asks how a small change in x would change that same loss. If x influences several downstream values vj, every path contributes.
    

    ∂L∂x=∑j=1M∂L∂vj∂vj∂x
    

    One shared-weight example. Let r₁=wx₁ and r₂=wx₂, with one shared scalar w. Take x₁=1, x₂=3, target values y₁=1 and y₂=0, and initial w=0.2. Use a sum of two squared-error terms; there is no batch-mean factor in this separate example.
    

    L=12(r1−y1)2+12(r2−y2)2
    

    PathForward valueIncoming gradientLocal derivativeContribution to shared w
    

    w → r₁ → Lr₁=0.2r₁−y₁=−0.8x₁=1−0.8×1=−0.8
    

    w → r₂ → Lr₂=0.6r₂−y₂=0.6x₂=30.6×3=1.8
    

    

    ∂L∂w=−0.8+1.8=1;wnew=0.2−0.1×1=0.1
    

    The loss starts at 0.5. A fresh forward pass at w=0.1 gives predictions 0.1 and 0.3, and loss 0.45. The two paths prefer opposite directions; their sum defines the update. This is the same accumulation principle used when a convolution kernel is shared across image positions.
    

    Read the units: a gradient is loss change per unit change in its variable. Multiplying the incoming loss-per-output slope by an output-per-weight slope produces a loss-per-weight slope. The learning rate then sets the size of the parameter change.
    

    Checkpoint: why save the forward values?
    The derivative of wx with respect to w needs the x used by that forward pass; ReLU needs the saved sign of its preactivation. Updating a weight before all its gradient contributions are calculated mixes parameter snapshots and no longer differentiates the original loss.

    DERIVATION 3 / REVERSE EVERY READ OF THE INPUT
    

    The input gradient adds overlapping patches back into image coordinates.
    

    For the live miniature, use one input channel, one shared 2×2 kernel, stride 1, no padding and no dilation. Its 3×3 image produces a 2×2 preactivation map.     DERIVATION 5 / ROUTING, OVERLAP AND NONDIFFERENTIABLE POINTS
    

    A gate decides which paths receive a gradient; overlap decides where paths add.
    

    Consider a 2×2 max pool with stride 1 on the following 3×3 activation map. Every pooling window has the same unique winner, the central 9. This overlapping example differs from the live symbol CNN’s non-overlapping stride-two pooling.

    The center receives 0.1+0.2+0.3+0.4=1. Copying only the last contribution would lose three paths. For a window with a unique maximum, every non-winning cell receives zero from that window.
    

    At a tie, the ordinary derivative is not unique. In the block [[4,4],[1,0]], two cells attain the maximum. Sending an incoming gradient of 1 to one selected maximum is a valid convention; splitting it as 0.5 and 0.5 is another valid subgradient. A specific framework operation chooses its own routing convention. A finite-difference check at this exact tie need not equal a selected convention.
    

    ReLU uses its saved preactivation. For Z>0 its local derivative is 1; for Z<0 it is 0. At exactly zero, this miniature chooses 0. The sign of the incoming gradient does not decide whether the gate opens: the saved Z does.
    

    In a concrete variant of the miniature, setting its convolution bias to −1.5 makes all four preactivations negative: [[−0.4,−1.1],[−1.3,−0.9]]. Then h is all zero, the convolution-weight and dense-weight gradients are zero, but the dense-bias gradient remains approximately [0.524979,−0.524979] for true class B.     Checkpoint: what does an all-zero feature map imply?

Another input may open different gates, and dense output biases still receive gradients. This is a local statement about the saved forward pass.

    Technical reference: training, experiments, system design and source map

    A / The complete learning loop
    

    1. Define the task. Choose inputs, labels, classes and a cost of error.
    2. Collect or generate data. Record source, consent/permissions where relevant, labels and conditions.
    3. Split by independent unit. Use separate images for the synthetic lab, complete rounds/players for RPS, and clips/sessions for video evaluation.
    4. Fit. Training data determines weights, preprocessing statistics or centroids.
    5. Validate. Use validation data to choose settings and inspect learning curves.
    6. Freeze and test. Report errors on data not used to make those choices.
    7. Inspect failures. Identify confusion, missing detections, identity jumps, latency and interaction mistakes.
    8. Improve one thing. Compare under the same protocol and keep new final-test data if earlier test results guided revisions.
    

    A low training loss with weak validation performance suggests a generalization problem. More epochs may worsen it. Poor training and validation performance can also reflect insufficient capacity, optimization trouble, bad labels or mismatched input preprocessing. Inspect actual examples before choosing a remedy.
    

    Data augmentation changes training examples, such as small shifts or noise. Apply only transformations that preserve the intended label. Rotating a plus by 45 degrees creates an X in this task, so that transformation changes its class.
    

    B / Architecture and optimization choices
    

    Convolution learns local feature extractors. ReLU introduces nonlinearity. Pooling reduces spatial resolution. Flattening reshapes. A dense layer maps features to class logits. Softmax normalizes class scores. Cross-entropy penalizes low score for the true class. Backpropagation supplies gradients, and the optimizer updates parameters.
    

    The toy network is intentionally small and task-specific. Real detectors need box regression, classification, candidate matching, suppression and much more diverse data. Training the symbol CNN does not retrain MediaPipe or COCO-SSD. Fine-tuning a detector requires compatible labeled boxes, a training/export workflow and a separate evaluation.
    

    The lab code uses a fixed, pre-shuffled dataset order with shuffle:false. Seed 314 controls image generation and weight initialization. The network starts fresh when retrained. A run is reproducible enough for learning comparisons without promising identical GPU results on every device.
    

    Softmax outputs sum to one. This does not establish calibration on human drawings, unseen cameras or novel classes. A classifier trained on three classes still assigns scores to an image of something else. Add an abstention policy only after defining and evaluating it.
    

    C / Confusion, precision, recall and coverage
    

    Our confusion matrices put true classes in rows and predicted classes in columns. Diagonal entries are correct classifications. Overall accuracy is diagonal sum divided by the number of scored examples. In the fractions below, TP means true positives, FP means false positives, and FN means false negatives.
    

    Precision=TPTP+FP
    Recall=TPTP+FN
    F1=2×precision×recallprecision+recall
    

    Define the positive class and matching rule first. For object detection, a common evaluation matches a predicted box to a human box using an IoU threshold and class agreement. One target cannot count as multiple true positives. Average precision summarizes a precision–recall curve under a defined matching protocol. This workshop does not compute detector AP.
    

    Example: 10 true positive detections, 5 false positives and 2 misses give precision 1015 and recall 1012. Report undefined ratios when a denominator is zero rather than inventing a perfect score. For early RPS, also report attempted rounds with no usable prediction.
    

    D / Why the RPS model can fail honestly
    

    It cannot read intention. If all three future moves show the same fist before cutoff, the observed inputs may carry little or no separating information. A confident nearest-centroid choice is still possible because the implementation always selects a nearest class when features exist. It has no calibrated confidence threshold.
    

    Four finger chains begin at landmarks 5, 9, 13 and 17. For each, sum MCP-to-PIP, PIP-to-DIP and DIP-to-tip segment distances. Divide MCP-to-tip distance by that sum. The final eight-feature vector combines position-like straightness and time-normalized change.
    

    Current-camera recognition separately maps Closed_Fist, Open_Palm and Victory to RPS at category score ≥0.5. The simulation path uses explicit finger thresholds: open ≥0.8, curled <0.65. Built-in traces demonstrate a workflow rather than a human-motion benchmark.
    

    Source/timing changes reset incompatible data. Personal camera training discards artificial examples before collecting the real training set. Test rows do not update centroids. At least three training rounds per class permit fitting; that minimum is not enough to claim broad predictive performance.
    

    E / A detector and a tracker solve different problems
    

    Detection asks where an object is in one image. Association asks which detection belongs to an object observed earlier. A filter can smooth observations. A motion model can predict a future state. Optical flow estimates image motion. These methods are related but not interchangeable.
    

    Ball Remix currently associates by nearest center after starting with the largest box. Two nearby balls, occlusion or a sudden camera move can break identity. A smoothing lag can also affect the next nearest-center choice because the implementation stores the smoothed previous position.
    

    Possible extensions include a maximum-distance gate, size consistency, estimated velocity, an appearance descriptor or a multi-object assignment method. State the change, preserve comparison labels and inspect identity errors. A Kalman filter would add an explicit motion/uncertainty model, but this starter does not implement one.
    

    F / Browser execution, resources and reproducibility
    

    TensorFlow.js manages tensors and may execute on WebGL or CPU. The CNN lab yields between training batches, supports cancellation and disposes intermediate tensors. Ball Remix prefers WebGL and falls back to CPU if backend setup fails. The hand tasks use local MediaPipe WASM with a CPU delegate.
    

    Canvas sampling, video decode and UI work also consume time. Repeated CPU-to-GPU uploads or tensor copies can dominate a tiny network. Measure the full path instead of treating model inference time as the whole experience.
    

    Stopping a camera must stop every media track. Hiding a video is not stopping capture. Epoch tokens prevent late async work from attaching to a newer session. Cancellation must wait for in-flight work before reusing shared model/input resources.
    

    For repeatable evidence, save model/version, asset hashes, source clip, sample times, threshold, smoothing, backend and human labels. Runtime logs and test results remain software-test evidence rather than proof of accuracy on every device.
