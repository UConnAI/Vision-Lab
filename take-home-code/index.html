BUILD THE LOOP

Four pieces turn data into a video.

01

Read the CSV

Use Frame as a dictionary key. Rows may be out of order or missing.

positions = load_positions(csv_path)
row = positions.get(frame_index)
02

Remember a short history

A bounded deque keeps the newest eight observations. A missing position inserts None.

history = deque(maxlen=8)
history.appendleft(point_or_none)
03

Draw on each frame

Connect adjacent valid observations. Break the line at a missing row; do not invent an unseen path.

success, image = capture.read()
draw_frame(image, history, point)
04

Write the whole video

Continue until decoding ends, using the original dimensions and frame rate.

writer.write(image)
frame_index += 1

TRAIN IT HERE / THREE SMALL CNNS

Can a tiny CNN move your sticker?

Train three randomly initialized networks directly in this browser on the selected video. Each takes a 32 × 18 RGB frame and predicts two normalized center coordinates. All three use the same chronological 60% training / 20% validation / 20% test split and seed 314. The best validation epoch is kept; the final test frames are used only for the comparison table.

Compare with the baseline. Predicting the average training position can already work well when a ball barely moves. More layers do not guarantee a better result. Tiny B has fewer parameters than Tiny A because its second pooling step shrinks the dense layer. After training, choose a CNN under Position source above to drive the rock sticker with its actual predictions. CSV trails are hidden in CNN mode; predictions update at up to about 10 Hz.

These are center regressors trained on visible frames from one clip—not pretrained object detectors. They always output a point, including when no ball is visible. The labels are supplied coordinate estimates, so the table measures agreement with held-out CSV coordinates, not verified tracking accuracy. A new clip or edited CSV clears the trained models. Neighboring frames remain related even with a chronological split; testing on a different labeled video is a separate challenge.

See the three architectures and training objective

Tiny A: Conv(4) → MaxPool → Flatten → Dense(2). Tiny B: Conv(4) → MaxPool → Conv(8) → MaxPool → Flatten → Dense(2). Tiny C: Conv(8) → MaxPool → Conv(12) → MaxPool → Flatten → Dense(2). All convolutions use 3 × 3 kernels, same padding and ReLU; the output uses sigmoid. Adam uses learning rate 0.005. Loss is the mean squared difference between predicted and supplied normalized x/y coordinates.

target = [x / video_width, y / video_height]
loss = ((prediction - target) ** 2).mean()
optimizer.zero_grad()
loss.backward()
optimizer.step()

The downloadable Python implementation uses PyTorch. The browser version uses the bundled TensorFlow.js runtime on CPU. Their architectures match; identical weights or cross-runtime results are not promised.
